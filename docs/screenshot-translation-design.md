# 截图翻译设计

本文记录截图翻译的共享设计，等待最终确认后实施。它补充术语表与 ADR，不替代它们。

## 目标

让用户通过浏览器内快捷键或扩展菜单冻结当前标签页的可见画面，框选其中区域，并把区域内全部可见自然语言文字翻译成文本。用户也可以在独立工作区导入本地图片或剪贴板图片，框选后走同一条翻译链路。

截图翻译继续遵循现有目标语言规则：主导语言是中文时译为英语，否则译为简体中文。模型只翻译文字，保持阅读顺序、段落和列表结构，不解释图片，也不回答图片中的问题。

## 入口

点击扩展图标打开紧凑菜单：

1. **截图翻译**：进入当前网页的截图模式，同时展示快捷键。
2. **导入图片**：打开图片翻译工作区。
3. **设置**：以齿轮图标进入配置页。

浏览器内默认快捷键为 `Alt+Shift+S`，用户可从配置页提供的入口跳转到 `chrome://extensions/shortcuts` 修改。快捷键不注册为操作系统全局快捷键。

## 网页截图流程

1. 用户通过快捷键或菜单启动截图翻译。
2. 扩展捕获当前活动标签页的可见区域，不做滚动整页拼接。
3. 捕获结果覆盖在顶层页面上，形成冻结画面；实时网页在框选期间不可交互。
4. 用户拖出框选区域。松开后可以移动和缩放选框。
5. `Enter`、双击选框或点击确认按钮提交；`Escape` 或取消按钮退出。
6. 区域过小则不发请求，并提示重新框选。
7. 确认后退出冻结画面，恢复实时网页，在原框选区域附近打开截图翻译卡片。
8. 卡片显示截图缩略图、语向和流式译文；空间不足时自动换边并约束在视口内。

截图翻译卡片不会因点击网页其他位置而关闭。用户可以拖动标题栏避让页面内容；关闭按钮、`Escape` 或在同页开始新的截图翻译会关闭它。

卡片提供：复制译文、重试翻译、重新框选和关闭。重试复用当前截图；重新框选复用同一张冻结画面，不重新捕获可能已经变化的网页。

若当前页面无法承载扩展框选界面，扩展仍捕获可见区域，并把它载入图片翻译工作区继续操作。

## 图片翻译工作区

导入图片打开独立扩展标签页。工作区左侧为图片与框选区域，右侧为流式译文；它不依附于原网页。

支持三种无权限输入：文件选择、拖放、手动粘贴。支持 PNG、JPEG、WebP，单个源文件不超过 20 MB；GIF、SVG、PDF 和多页文档不在首版范围内。

图片载入后默认选中整张，按 `Enter` 即可翻译。用户也可以先修改框选区域，再通过 `Enter`、双击或确认按钮提交。修改选框本身不会自动发起模型请求。

工作区提供复制译文、重试翻译、重新导入和清空。工作区关闭时取消仍在进行的请求并释放图片。

## 剪贴板

默认不申请剪贴板读取权限，用户可在工作区按 `Ctrl/Cmd+V` 粘贴图片。

工作区提供“自动读取剪贴板图片”开关。用户主动开启时才申请可选的 `clipboardRead` 权限；授权后，进入工作区会自动载入当前剪贴板图片。剪贴板没有图片时保留正常导入界面，不弹出错误。

## 服务配置

文本模型和截图模型共用服务地址与 API Key，仅模型名称独立：

- 默认文本模型：`gpt-5.4-mini`
- 默认截图模型：`gpt-5.4-mini`

截图模型配置为空时回落到默认值，而不是回落到文本模型。已保存的旧默认值 `gpt-5.5` 会迁移到新默认值，其他自定义模型保持不变。服务返回“不支持图像输入”一类错误时，界面明确提示配置截图模型。

OpenAI 官方文档确认 `gpt-5.4-mini` 支持图像输入、Chat Completions 与流式输出；Chat Completions 用户消息支持文本和 `image_url` 内容块。因此实现继续使用现有 `/v1/chat/completions` 与 SSE 管线，不引入第二套 API 客户端：

- [GPT-5.4 Mini 模型说明](https://developers.openai.com/api/docs/models/gpt-5.4-mini)
- [Chat Completions API](https://developers.openai.com/api/reference/cli/resources/chat/subresources/completions)

截图翻译使用独立提示词。用户消息由“翻译契约文本”与内存中的图像数据组成；响应继续使用 ADR 0001 的首行语向标记和后续译文协议，因此现有流式解析器、错误重试和语向徽标可以复用。

## 图像处理

框选在冻结画面对应的位图上完成，不能从实时网页重新截图。CSS 坐标换算为位图坐标时必须考虑设备像素比、视口缩放和图片在工作区中的等比缩放。

只编码框选区域。为兼顾文字清晰度和兼容性：

- 最长边不超过 4096 像素，总像素不超过约 1000 万；超过时等比缩小。
- 优先保留 PNG；编码体积过大时转换为高质量 WebP。
- 不放大低分辨率图片。
- 不向模型发送冻结画面的框选区域之外内容。

## 隐私与生命周期

用户第一次启动截图翻译或导入图片时，扩展显示一次说明：确认的图像区域将发送到用户配置的翻译服务。确认结果只在本机保存为一个布尔设置，之后不再打断流程；配置页始终保留同样说明。

冻结画面、导入原图和截图只驻留内存，不写文件、不写 `chrome.storage`、不进入翻译缓存。网页截图的冻结画面保留到卡片关闭，以支持重新框选；图片翻译工作区中的原图保留到清空或关闭标签页。请求结束后，后台立即释放图像请求数据。

同一网页开始新截图时，取消旧请求并替换旧卡片。不同网页各自保留任务；图片翻译工作区拥有独立任务。关闭对应界面会立即中止请求。

## 权限

首版新增：

- `activeTab`：只在用户触发截图时临时捕获当前标签页。
- `commands` 清单项：注册浏览器内截图快捷键。
- 可选 `clipboardRead`：仅在用户主动开启自动读取时申请。

不为截图翻译新增永久的全站主机权限，不注册操作系统全局快捷键。

## 错误反馈

- 未识别到可翻译文字：保留图像，提示重新框选。
- 框选区域过小：不发请求，提示调整选框。
- 截图模型不支持图片：保留图像，提供配置截图模型入口。
- 鉴权失败：保留图像，提供配置页入口。
- 网络或服务暂不可用：保留图像，允许重试。
- 模型返回空内容：保留图像，允许重试。
- 同一请求已经输出部分译文后断流：展示错误，不自动重放，避免重复译文。

任何服务错误都不要求用户重新截图。只有截图本身无效时才要求重新框选。

## 实现边界

消息协议改为可辨识联合类型，明确区分文本翻译和截图翻译；响应事件继续共用 `lang`、`delta`、`done` 和 `error`。截图请求不进入现有文本 LRU。

截图框选 UI 只由顶层框架承载，避免现有 `all_frames` content script 在每个 iframe 各生成一套全屏遮罩。普通划词翻译继续保持每框架一套浮层，不改变 ADR 0003。

以下内容不在首版范围内：滚动整页截图、系统桌面或其他应用截图、批量图片、翻译历史、OCR 服务、本地 OCR、原位覆盖图片文字、看图问答、GIF、SVG、PDF 和多页文档。

## 验证

### 本地真实服务约束

仓库根目录的 `.env.local` 保存可用于真实端到端测试的服务地址和 API Key，并已由 `.gitignore` 排除。文件同时提供通用的 `OPENAI_BASE_URL` / `OPENAI_API_KEY` 与现有测试命名空间的 `TP_BASE_URL` / `TP_API_KEY`；任何脚本、日志、截图、错误信息和测试报告都不得输出密钥。

真实 E2E 必须以该文件中的服务为最终验收后端，不能只通过模拟响应宣告截图翻译完成。测试至少验证 `gpt-5.4-mini` 的文本翻译与截图翻译；测试素材只能使用仓库自带的无敏感信息 fixture，避免把真实页面内容发送到服务。运行前由测试命令显式加载 `.env.local`，仓库内文档和可提交文件只记录变量名，不记录变量值。

纯函数测试至少覆盖：

- CSS 坐标、设备像素比与位图裁剪坐标换算。
- 选框移动、缩放、最小尺寸和视口约束。
- 图片格式、20 MB 限制和缩放策略。
- 设置迁移与两个模型默认值。
- 文本和截图请求的类型分流。
- 多模态 Chat Completions 请求体。
- 截图错误映射与现有流式首行协议。

真实 Chrome E2E 至少覆盖：

- 快捷键和扩展菜单进入冻结截图模式。
- 框选、调整、取消和确认。
- 模型请求收到的只有框选区域。
- 实时网页恢复，卡片定位、拖动、驻留和关闭。
- 流式译文、复制、重试和重新框选。
- 同页任务替换、跨页任务独立和关闭时取消。
- 文件选择、拖放、手动粘贴与整图快速翻译。
- 可选剪贴板权限的开启、拒绝和无图片状态。
- 受限页面回落图片翻译工作区。
- 深色主题和高设备像素比。

## 验收标准

用户在普通网页中可以完成“快捷键 → 框选 → 调整 → `Enter` → 原位置附近查看流式译文”，失败后无需重新截图即可重试。用户也可以完成“扩展菜单 → 导入图片 → `Enter` → 查看译文”，默认不授予剪贴板读取权限。所有图片数据只在明确的界面生命周期内驻留内存，关闭界面后不可恢复。
