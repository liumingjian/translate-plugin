# iframe 里的选区：每个框架各挂一套浮层，而不是把选区上报给主文档

`all_frames: false` 时 content script 只跑在顶层文档里，iframe 内选中的文字既收不到 `mouseup`，也读不到选区 —— 嵌入式文档、评论区、富文本编辑器（大量用 srcdoc iframe）里划词图标一律不出。改成 `all_frames: true`，**每个框架各自持有一套浮层与端口**，谁的框架里有选区，图标就画在谁的框架里。同时打开 `match_about_blank`，否则 srcdoc / about:blank 框架注入不进去。

## Considered Options

- **子框架只上报，主文档渲染** —— 卡片画在顶层，不会被小框架夹住，是体验上限。代价是要自己搭一套 postMessage 协议：坐标逐层换算、嵌套 iframe 逐级转发、滚动与关闭都要跨框架同步，且跨源框架拿不到「是哪个 iframe 发来的」以外的任何信息。相对于它解决的问题，这套协议太重。
- **每框架一套浮层**（选中）—— 几行 manifest 改动，跨源、嵌套、srcdoc 一视同仁，因为每个框架看到的都是「一个普通文档」。
- **只在同源 iframe 里注入** —— 覆盖不到嵌入式阅读器这类最需要划词的场景，跨源恰恰是主力。

## Consequences

- **卡片会被框架视口夹住**。卡片宽 380px，放进只有几十像素高的框架里就只剩一条 —— 这是本决策明确接受的代价。真要解决，只能回到「子框架上报、主文档渲染」那条路。
- 子框架的浮层收不到主文档的 `mousedown` 和 `Escape`，用户点回主页面时卡片会一直挂着。补法是子框架监听自己的 `blur`：页面整体仍可见（`visibilityState === 'visible'`）才关，切标签页回来译文还在。
- 浮层实例数从 1 变成「框架数」。每个实例只是一个空的 shadow host，代价可忽略；但广告框架这类地方也会挂上，属于无害的浪费。
- 翻译端口是按框架建的，同一页里不同框架的翻译互不干扰。
